AI Return Fraud Detection

What left the warehouse
isn't always
what comes back.

ReturnGuard compares the product a customer received against the product they returned — at the pixel level, before the refund clears, not after a warehouse worker eyeballs it three days later.

Return fraud hides in the gap between pickup and refund. A customer receives the correct item, then returns something else — damaged, substituted, or simply not what shipped — and still collects a full refund. Most platforms only catch this at manual inspection, well after the money has already moved.

ReturnGuard also analyzes customer return history. A first-time returner gets the benefit of the doubt. A customer with a pattern of returns that triggered fraud flags faces tighter thresholds — the model adapts.

Standard embedding threshold. A clean return history earns the benefit of the doubt — most returns are genuine.

How ReturnGuard Works

A two-phase pipeline, six systems, one verdict. Here's exactly what happens from image upload to refund decision.

PHASE 1 — DELIVERY REGISTRATION
01

Capture baseline evidence

At dispatch, a warehouse operator uploads three photos of the product: front, back, and side. Backgrounds are automatically stripped using rembg. This is the ground truth — the only reference the system has for this specific product instance.

02

Generate DINOv2 embedding

Each image is passed through DINOv2, a self-supervised vision transformer. The resulting embeddings capture product identity in a way that's robust to minor lighting, angle, and presentation differences. All three are stored as the delivery fingerprint and assigned an integer Order ID.

PHASE 2 — RETURN VERIFICATION
03

Embedding similarity check

When a return is submitted, the same process runs on the return images. Cosine similarity is computed between delivery and return embeddings for each view. A quality-weighted average (sharper images weighted higher using Laplacian sharpness scoring) produces the final similarity score.

avg_score > 0.60 → RETURN_ACCEPTED immediately avg_score ≤ 0.60 → escalated to VLM agents
04

Parallel VLM analysis

For scores below the threshold, three independent Vision-Language Model agents analyze the front, back, and side view pairs simultaneously. Each agent receives the delivery image, the return image, and the similarity score as a qualitative label. They look for product-specific differences — shape, color, labels, damage, structural features — while explicitly ignoring presentation artifacts like lighting, angle, and cropping.

05

Final judge synthesis & risk scoring

A coordinator LLM reads all three VLM reports and produces a final structured verdict with a fraud risk score (0–100). High-precision is the explicit objective — the system prefers false negatives (letting fraud through) over false positives (wrongly blocking a genuine return) to protect customer trust.

The four possible verdicts

RETURN_ACCEPTED
Return Accepted

Embedding similarity exceeded 0.60. The returned item is visually consistent with the delivered item. No VLM review required — the pipeline terminates here and the refund can proceed.

VLM Accepted
Return Accepted (via VLM)

Similarity was below 0.60, but all three VLM agents confirmed the product matches. Presentation differences were ruled out as the cause of the low score.

Human Review
Requires Human Review

VLM agents reached ambiguous or conflicting conclusions. A human reviewer receives the full evidence package — all three agent reports plus the final judge synthesis — and makes the call.

Rejected
Return Rejected

Multiple VLM agents identified convincing product-specific discrepancies that cannot be explained by presentation. The return is flagged as fraudulent and the refund is blocked.

System Architecture

Two entry paths. One decision engine. Every component is deterministic — the same inputs produce the same verdict path, with a full audit trail.

Stack

LangGraph — stateful multi-agent workflow with conditional routing

LANGUAGE MODEL
Gemini 2.5 Flash (via LangChain Google GenAI) — VLM review + final judge
BG REMOVAL
rembg — automatic background stripping and bounding-box crop
BACKEND
Flask (Python) — REST API + Jinja2 template serving
DATABASE
SQLite (request.db) — Orders table with full verdict + score audit trail
